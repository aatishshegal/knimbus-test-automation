Architecture & Modularization Design

The Profile Details test automation folder (tests/portal/profile-details/) is engineered strictly adhering to clean design principles, strict Single Responsibility Principle (SRP) for Page Object Models (POMs), Playwright custom fixtures, and complete data-driven isolation.

🏛️ Page Object Model (POM) SRP
Every tab inside the User Profile has a dedicated Page Object class in src/pages/portal/profile-details/ (ContactPage, EnrollmentDetailsPage, IdAccessInfoPage, PasswordPage, ProfileBasicInfoPage, WorkEducationPage). God classes are strictly prohibited.
📦 Playwright Fixture Injection
Page Objects are instantiated automatically using custom Playwright fixtures defined in src/fixtures/index.ts. Spec files receive page objects directly as parameters, eliminating manual class instantation in test bodies.
📊 Data-Driven JSON Isolation
Zero test strings or locators are hardcoded in test specs. All validation messages, limits, boundary values, and test inputs are read from structured JSON files in tests/test-data/.
⚡ Global Session & API Preconditions
Authentication state is reused via global setup states. Admin settings (e.g. mandatory field requirements, 2FA toggles) are set directly via AdminApiService backend endpoints rather than slow UI interactions.
🔄 Dynamic Mandatory & Optional Field Adaptation
Tests dynamically inspect DOM field labels for red asterisks (*) and required attributes via isFieldMandatory(). If a field is configured as mandatory, empty submits strictly assert required errors; if optional, empty saves complete cleanly without false failures.
