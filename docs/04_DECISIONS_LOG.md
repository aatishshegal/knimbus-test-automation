# Architectural Decision Records (ADR)

| Date | Decision | Reason | Alternatives Considered | Impact |
| :--- | :--- | :--- | :--- | :--- |
| 2026-07-02 | **UI-Based Test Data Setup** | Backend APIs are not available in the older codebase for seeding data or configuring settings. We must use the Librarian Dashboard UI to set up test prerequisites. | Generating data via API (rejected due to missing endpoints). Direct Database queries (rejected as too complex/risky without proper dev support). | **High**. UI setup is inherently slower. We must implement strict Session State (`storageState`) management to avoid logging into the admin portal repeatedly. Global Setup scripts will become a critical part of the framework. |
| 2026-07-02 | **DOM Selectors over `data-testid`** | The application is mostly Angular Server Side Rendered, and developer support for adding `data-testid` attributes is not guaranteed. | Using strict `data-testid` attributes (rejected). | Tests will rely on Playwright's role-based and text-based locators (e.g., `getByRole`, `getByText`). This is more brittle to UI translation/copy changes but aligns with what is available. |
| 2026-07-02 | **Sequential Execution (Initial Phase)** | To safely handle global state mutations on the Librarian Dashboard without risking race conditions against Portal tests, we are forcing sequential execution (`fullyParallel: false`, `workers: 1`). | Using parallel execution out of the gate. | **Medium**. Slower test execution overall, but guarantees zero flakiness from shared global settings while the framework is being established. We will re-evaluate parallelization using tags later. |
| 2026-07-15 | **Database Verification via MCP** | We integrated MySQL MCP for test verification. While test data setup MUST still use the Librarian Dashboard UI, we will use direct database queries (SELECT only) to verify system state and assertions without relying on the UI. | Full database setup (rejected to prevent accidental data corruption/desync). | **Medium**. Speeds up assertions and gives deeper visibility into failures. |
| 2026-07-16 | **Environment Variable Test Data** | Hardcoded test user and admin credentials in fixtures have been completely removed in favor of `.env` files (`process.env`). | Keeping hardcoded credentials for simplicity (rejected as a security anti-pattern). | **Low**. Minor refactor but establishes secure baseline for CI/CD pipeline integration. |
| 2026-07-16 | **Smart SPA Toggle Navigation** | Addressed Playwright pointer interception timeouts caused by stateful CSS toggles (e.g., Librarian left menu) by implementing a try-catch fallback pattern (`navigateToUserManagement`). | Using `force: true` everywhere (rejected as it triggers invisible elements) or hardcoded timeouts (brittle). | **High**. Prevents cascading flakiness across chained admin setup steps during test data preparation. |
| 2026-07-29 | **API-Based Test Data Setup** | Successfully reverse-engineered the internal User Management and Security Settings APIs used by the Librarian Dashboard. We migrated from UI-based setup to API-based setup to eliminate UI flakiness and significantly speed up test preconditions. | UI-Based Test Data Setup (rejected as too slow and flaky for large test suites). | **High**. Replaced all UI admin scripts with `AdminApiService`. Drastically reduces test setup time from ~15s to ~1s per test and ensures absolute stability. |
